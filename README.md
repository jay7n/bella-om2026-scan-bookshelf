# 扫书 · AI 书架速览器

> 拍一张书架照片，AI 读出书脊上的书名，给每本书写一句话简介和推荐理由，做成可以左右滑的卡片。
>
> 给社区图书角用的小工具 —— 不用把书抽出来，就知道该借哪本。

## 一、背景：一个四年级孩子站在书架前的十分钟

社区图书角、班级图书角里的书，都是密密麻麻立着排的：

- **书脊上的字又小又花**，站着根本看不清
- **想知道一本讲什么，只能抽出来翻**，翻完再塞回去
- 一排三十本，挑一本要花十分钟，最后常常**什么也没借成**

大人可以掏手机搜书名，但孩子不行 —— 一是得先看清书脊上写的到底是哪几个字，二是搜出来的简介是写给大人看的（"认知发展""叙事结构"），孩子看不懂。

**这件事的本质不是"书太少"，是"信息对不上"**：书的信息写在书脊上，而孩子需要的信息（这本书讲什么、读起来什么感觉、适不适合我）没有任何地方写着。

于是有了「扫书」：**把整排书变成可以刷的卡片，每张卡片用孩子听得懂的话说清一件事。**

---

## 二、这是什么

三步，不到 30 秒：

```
① 拍          ② 认                  ③ 滑
对着书架      AI 一行一行读书脊      每本书一张卡
拍一张        认出一本就先出一张卡    左右滑，决定借哪本
```

<p align="center"><img src="docs/screenshots/card.jpg" width="300"></p>

每张卡片上有六样东西，按孩子做决定的顺序排列：

| 位置 | 内容 | 为什么放这 |
|---|---|---|
| 封面 | 真实书封或 AI 生成的封面 | 先看脸，和站在书架前一样 |
| 书名 / 作者 | 补齐书脊上看不清的字 | 这是最基础的信息 |
| **推荐条** | 👍 推荐 + 一句为什么 | 直接回答"适不适合我" |
| 气质标签 | 轻松 / 好玩 / 有点好奇 / 三年级 | 三秒判断这本书"读起来什么感觉" |
| **钩子** | 一句让人想读的话 | 决定"要不要借"的关键 |
| 一句话简介 | 35 字以内的大白话 | 说清讲什么 |

## 三、功能

### 3.1 识别

| 功能 | 说明 |
|---|---|
| 拍照识别 | 一次最多 30 本，视觉模型逐行读书脊 |
| **边认边出卡** | 不等奖全部识别完，认出第一本第一张卡就出来（首卡 3~5 秒） |
| 相册选图 | 也可以从相册选一张现成的照片 |
| 识别失败提示 | 认不出时告诉孩子怎么办（正对、光线足、别开闪光灯、只拍一排） |

### 3.2 浏览

| 功能 | 说明 |
|---|---|
| 闪卡 | 左右滑动 / 点左右两侧 / 点按钮，三种翻页方式 |
| 自动轮播 | 5.2 秒自动翻页，手动操作即刻停止 |
| 详情页 | 豆瓣评分、简介、短评 + 四段深度解读（讲什么 / 为什么值得读 / 读之前要知道 / 最适合谁） |
| 收藏 | 单本收藏，随时取消 |

### 3.3 封面

| 功能 | 说明 |
|---|---|
| 真实封面 | 从豆瓣抓取，服务端代抓绕过防盗链 |
| AI 画封面 | 豆瓣没有的书，用文生图现场画一张（画面内不出现文字） |
| 程序化封面 | 断网或生成失败时，用书名生成色块封面，**永远不留白** |
| 本地缓存 | 画过的封面存在手机上，下次秒开 |

### 3.4 个性化推荐

这是本作品最核心的功能，见 [第七节](#七个性化推荐)。

### 3.5 书架

| 功能 | 说明 |
|---|---|
| 一册一书架 | 每拍一次存成一册，可按日期区分 |
| 书架视图 | 封面墙平铺，一眼看到这次扫了什么 |
| 起名 | 可以给书架起名字（"三楼靠窗那排"） |
| 回看 | 点任意一册，用闪卡再刷一遍 |
| 收藏切换 | 书架和闪卡里的收藏状态同步 |

### 3.6 使用者画像

| 项 | 内容 |
|---|---|
| 年级 | 一年级 ~ 六年级 |
| 性别 | 男生 / 女生 / 先不说 |
| 性格 | 好奇、安静、爱笑、爱动、认真、爱问为什么、怕吓人、喜欢动手 |
| 偏好 | 科普、故事、漫画、动物、太空、历史、实验、神话、侦探、搞笑 |
| 补充 | 自由输入 60 字 |

**全部存在本机**（localStorage），不上传服务器。

## 四、一次完整的使用流程

1. 打开网页（扫码或链接），看到首页
2. （可选）填写「我是谁」：年级、性格、喜欢的类型
3. 点「拍下这排书」，对着书架拍一张 —— 只拍一排，正对，光线足
4. AI 开始识别，书名片一张张蹦出来，被推荐的会亮起 👍
5. 自动进入闪卡，左右滑着看
6. 看到想借的，点「☆ 收藏」；想多了解，点「详情 ›」
7. 滑完，收藏的书在「收藏」里；这一册书在「历史」里
8. 下次来，首页会出现「继续上次的书架」

## 五、技术实现

### 5.1 整体架构

```
手机浏览器（Next.js 前端，纯 CSS，无 UI 库）
  │
  ├─ 拍照 → 本地压缩（长边 1536 / JPEG 0.72，约 150~250KB）
  │
  ├─ POST /api/scan ──► DeepSeek 视觉模型
  │                     流式返回 JSON Lines，一行一个书名
  │                     │
  │                     ├─ 收到第一个书名 → 立刻出卡
  │                     ├─ 并发查豆瓣封面（4 路）
  │                     └─ 并发写简介与推荐（6 路）
  │
  ├─ GET /api/cover ───► 豆瓣图片（服务端代抓 + 三层缓存）
  ├─ GET /api/enrich ──► 简介 / 钩子 / 推荐判断
  ├─ GET /api/detail ──► 豆瓣评分短评 + 四段解读
  └─ GET /api/cover-gen ► 火山方舟 Seedream 生成封面
```

### 5.2 为什么用两个模型

| 任务 | 用谁 | 为什么 |
|---|---|---|
| 看图读书名 | 视觉模型 | 这是它的强项，一次调用读完一整排 |
| 写简介 / 判断推荐 | 文本模型 | 需要"说人话"和按画像判断，视觉模型做不好 |

**关键原则：不让模型干"服务器能干的活"。**

书名匹配、封面抓取、豆瓣评分都是代码做的；模型只做两件事 —— 看图读字、说人话。让语言模型去查数据，它只会编。

### 5.3 接口

| 接口 | 方法 | 作用 | 限流 |
|---|---|---|---|
| `/api/scan` | POST | 收图片二进制，NDJSON 流式返回书名 | 5 次/分 |
| `/api/search` | GET | 豆瓣搜索 + 可信度匹配 | 60 次/分 |
| `/api/enrich` | GET | 简介 / 钩子 / 气质词 / 推荐判断 | 80 次/分 |
| `/api/detail` | GET | 豆瓣评分短评 + 四段解读 | 40 次/分 |
| `/api/cover` | GET | 豆瓣封面代理（带 Referer） | 400 次/分 |
| `/api/cover-gen` | GET | 文生图封面 | 3 次/分 |

### 5.4 几个关键设计

**① 边认边出卡**

不等奖全部识别完才渲染。书名一到就开始查封面、写文案，首张卡 3~5 秒可见，而不是等 20 秒看到一片空白。

**② 豆瓣封面必须服务端代抓**

实测数据：不带 `Referer` 返回 **418**，`Referer` 不是豆瓣域名返回 **403**。浏览器的 `fetch` 不能改 `Referer`，所以只能由后端代抓并缓存。

**③ 生成的图片不能存 URL**

文生图返回的图片地址约 24 小时过期，必须当场下载转成 dataURL 存本地。

**④ 封面缓存三层**

| 层 | 命中耗时 |
|---|---|
| 前端 localStorage | ~0 ms |
| 服务端内存 | ~4 ms |
| 服务端磁盘 `.cache/covers` | ~200 ms |
| 豆瓣原图 | 3~8 s |

**⑤ 模型名会下架**

配置的图片模型如果返回 404，自动按备选链降级，不会因为一个名字写错就整个功能挂掉。

**⑥ 限流**

应用是公网可访问的，而识别和生图是付费调用。6 个接口都按 IP 做了滑动窗口限流，防止被刷额度。

## 六、创新点

**① 把"整排书"当成一次输入，而不是一本一本地查**

常见的做法是扫一本书的条形码。但社区图书角的问题不是"我要找某一本"，是"我不知道有哪些书、该选哪本"。所以这里让 AI **一次读一整排**，把选择变成浏览。

**② 推荐不是打分，是"说人话的判断"**

每本书除了"适不适合"，还给一句具体的理由：

> 👍 推荐 ｜ 你爱问为什么又喜欢动物，这本正对路

而且允许它说"不太合" —— 不硬夸。

**③ 推荐的理由会随画像变化**

同一个书架，填不同的年级和偏好，推荐结果不同。文案缓存也按画像分 key，改画像会重新生成。

**④ 永远不留白**

豆瓣没有封面 → AI 现画；AI 也失败 → 程序化色块封面。任何情况下卡片都是完整的。

## 七、个性化推荐

### 怎么判断

填写画像后，每本书的文案请求会带上画像信息，模型额外返回两个字段：

| 字段 | 取值 | 说明 |
|---|---|---|
| `fit` | 很合适 / 可以试试 / 不太合 | 适不适合这个孩子 |
| `reason` | ≤ 22 字 | 一句话说明为什么 |

提示词里明确要求：

> 必须具体。比如「你喜欢动物，这本全是真实的动物故事」。不确定就选「可以试试」，不要硬夸。

界面上一律显示为「**👍 推荐**」，不暴露"很合适"这种内部措辞。

### 筛选

填过画像后，闪卡页左侧出现「仅显示推荐」按钮，一点只留被推荐的书，再点恢复全部。

## 八、AI 使用说明

本项目**大量使用 AI**，性质分两种：

| | 说明 |
|---|---|
| **作品功能** | 运行时调用大模型：识别书脊、写简介、判断推荐、生成封面 —— 这是产品本身 |
| **开发过程** | 全部代码由 AI 编程助手（DeepSeek Harness）编写 —— 这是实现方式 |

实际工作方式是：

```
我们提出需求 → AI 写代码 → 我们试用，发现哪里不对 → AI 修改
```

这条循环在两天里跑了上百次，**每一次的方向都是人定的**：做什么功能、文案用什么语气、按钮放哪里、哪里"看着不对"，全部由学生和家长判断。

完整说明（含逐项分工）见 **[AI-使用声明.md](AI-使用声明.md)**。

## 十、安装与运行

### 10.1 环境要求

| 项 | 版本 |
|---|---|
| Node.js | **≥ 20.9**（Next.js 16 的要求） |
| 包管理器 | pnpm 或 npm |
| 网络 | 需能访问 DeepSeek API |

### 10.2 本地运行

```bash
# 1. 拉代码
git clone https://github.com/jay7n/bella-om2026-scan-bookshelf.git
cd bella-om2026-scan-bookshelf

# 2. 配置环境变量
cp .env.example .env.local
# 用编辑器打开 .env.local，填入你的 key

# 3. 装依赖
pnpm install        # 或 npm install

# 4. 启动
pnpm dev            # 或 npm run dev
```

打开 http://localhost:3000

### 10.3 必须配置的环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | ✅ | 识别书名 + 写简介，不填则识别功能不可用 |
| `ARK_API_KEY` | 可选 | 火山方舟，用于 AI 生成封面；不填则只用程序化封面 |
| `DEEPSEEK_BASE_URL` | 可选 | 默认 `https://api.deepseek.com` |
| `DEEPSEEK_VISION_MODEL` | 可选 | 默认 `deepseek-flash` |
| `DEEPSEEK_TEXT_MODEL` | 可选 | 默认 `deepseek-flash` |
| `ARK_API_BASE` | 可选 | 默认 `https://ark.cn-beijing.volces.com/api/v3` |
| `ARK_IMAGE_MODEL` | 可选 | 默认 `doubao-seedream-4-0-20260415` |

**没有 key 也能跑通界面**：用内置的模拟服务

```bash
node scripts/mock-deepseek.mjs                       # 另开一个终端
# 然后在 .env.local 里设 DEEPSEEK_BASE_URL=http://127.0.0.1:4000
```

### 10.4 手机访问

电脑和手机连同一个 WiFi，用：

```
http://<电脑主机名>.local:3000
```

比 IP 稳 —— 路由器重新分配 IP 也不会失效。

> Next.js 开发服务器默认只让 localhost 加载 JS，手机用其它地址会 403。`next.config.mjs` 已自动把本机所有 IP 和主机名加入 `allowedDevOrigins`。

### 10.5 生产构建

```bash
pnpm build
pnpm run start:production      # 相当于 next start -H 0.0.0.0 -p 3000
```

### 10.6 部署

已部署在 Sealos Devbox（HTTPS 公网地址）。

完整步骤见 **[docs/DEPLOY-sealos.md](docs/DEPLOY-sealos.md)**，包含 Devbox 与容器镜像两种方式、环境变量配置、以及部署后的自查命令。

## 十二、已知限制

| 限制 | 说明 |
|---|---|
| 识别率依赖照片 | 反光、侧拍、书脊破损都会掉；正对、光线足、只拍一排效果最好 |
| 30 本上限 | 再多会摊薄单本书在画面里的像素，识别率下降 |
| 豆瓣收录不全 | 小众书拿不到真封面，用 AI 生成或程序化封面 |
| 数据存本地 | 换浏览器或清缓存就没了，没有账号系统 |
| 需要联网 | 识别和文案都依赖模型 API |
